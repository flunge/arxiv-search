\issue{IFG for Non-Continuous Trajectory\textcolor{red}{$@$R2}} 
IFG maintains instance consistency even when objects become occluded and reappear. 
Though Eq.1–3 assume continuity, our implementation handles non-continuous cases.
To clarify, we introduce \textbf{visibility} $v_i^t \in \{0,1\}$ and \textbf{last visible frame} $\tau(i,t)$:
\vspace{-2ex}
\begin{equation*}
v_i^t = 
\begin{cases}
    1 & \text{if instance } i \text{ is visible at frame } t \\
    0 & \text{(occluded or out-of-view)} 
\end{cases}
\end{equation*}
\vspace{-3ex}
\begin{equation*}
\tau(i,t) = \max\{t' \mid t' < t, v_i^{t'} = 1\}
\end{equation*}

\vspace{-1.5ex}
\noindent If $i$ has no prior visible frame, $\tau(i,t)$ is undefined. Refined offset becomes as below. Motion map $h^t$ (Eq.4) propagates features from $\tau(i,t)$ to $t$ to reconnect post-occlusion states.

\vspace{-4.5ex}
\begin{equation*}
F_{i_{\text{offset}}}^t = 
\begin{cases}
    \begin{aligned}
    &(x_i^t - x_i^{\tau(i,t)},\ y_i^t - y_i^{\tau(i,t)},\ z_i^t - z_i^{\tau(i,t)}), 
    \end{aligned} \\
    \quad \quad \text{if } v_i^t = 1 \text{ and } \tau(i,t) \text{ exists} \\
    0,  \quad \text{otherwise}
\end{cases}
\end{equation*}

% The offset $ F_{i_{\text{offset}}}^t $ is defined as the 3D coordinate difference between $(x_i^t, y_i^t, z_i^t)$ and $(x_i^{\tau(i,t)}, y_i^{\tau(i,t)}, z_i^{\tau(i,t)})$ \textbf{only if} the object $i$ is valid at time $t$ ($v_i^t = 1$) and the timestamp $\tau(i,t)$ exists. Otherwise, $F_{i_{\text{offset}}}^t$ is set to zero.

\issue{Model Design\textcolor{orange}{$@$R3}}
Thanks for the insightful questions! %Clarifications below:

\noindent \textbf{ControlNet vs. Cross Attention:} 
Cross Attention primarily handles \textit{non-spatial} conditions (e.g., text) to guide global semantics, while ControlNet specializes in \textit{spatially} structured inputs (e.g., edges) to enforce geometric alignment. The layout and flow we use belong to the latter.
%ControlNet enables finer pixel-level control in handling spatial layout.


\noindent \textbf{Overlapping Boxes in Instance Flow Rendering:}
We use depth order to prioritize the rendering of closer objects.


\noindent \textbf{Flow Map:} 
We convert flow to RGB to unify its representation with other image-like conditions, then reuse the pretrained VAE to accelerate convergence. 
%Raw flow can't align with 
%pixel-level 
%box projections.
%Separate VAE to encode flow map slows convergence.

\noindent \textbf{Backward Flow:} 
Backward flow increases computation and may introduce redundancy; it can be explored in future.



\noindent \textbf{Pseudo-Label Noise:}
We simulate noisy bounding boxes during training via random perturbations (jitter, missing boxes) to enhance robustness to pseudo-label noise.


\noindent \textbf{Depth Encoding:} We use cross-attention to fuse depth with box projections, as it models 
%object interactions and 
pairwise depth relationships.
